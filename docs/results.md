# 검증 지표 — 실측치

> 아래 수치는 전부 자동화된 게이트·골든의 실측이다. 골든은 **"옛 코드에서 실패함을 먼저 확인한
> 것만"** 채택한다는 규율을 따른다([methodology.md](methodology.md) §5).
> 기준: 대전 중구, 2026-07.

## 검색 품질

| 지표 | 값 | 방법 |
|---|---|---|
| hit@10 | **93.9** | 실사용형 115문항 종합 평가셋 — 정답 문서가 상위 10위 안에 드는 비율 |
| 상시 회귀 채점 | 160문항 | 서빙 데이터에서 역생성한 문항으로 주간 자동 채점(사람 없이 도는 품질 감시) |

이 게이트는 장식이 아니라 실제로 결정을 기각한다: 리랭커 후보 풀 축소 실험(30→20)은 응답을 33%
단축했지만 hit@10이 93.9→90.4로 게이트(92) 미달이라 **기각**됐다. 속도는 품질 게이트를 통과할
때만 산다.

## 수치 정확성 — 예산·재정

| 지표 | 값 | 방법 |
|---|---|---|
| 지방재정365 교차 대조 | **15개 연도 전수 일치(원 단위)** | 문서에서 구축한 예산 총액 ↔ 공식 재정 API 대조 |
| 예산 골든 | 45문항 전부 fail-first | 부서 총액·드릴다운·증감 분해·회계 분리의 회귀 가드 |
| 트리합 불변식 | unflagged 위반 0 | 예산 트리 부모=자식합 전수 재검산(주간) |

교차 대조의 실전 성과: "4개 연도에서 파싱이 과소하다"던 오랜 가설을 재정 대조 탐지기가 뒤집었다
— 실원인은 파싱이 아니라 서빙 단계의 문서 충돌 탈락이었고, 수정 후 15개 연도 전수가 원 단위까지
일치했다. **탐지기가 없었으면 엉뚱한 곳(파서)을 고치고 있었을 것이다.**

같은 대조가 빌드 파이프라인의 크리티컬 버그 2건(빌드 스크립트 실행 불가 회귀·차수 중복 제거 손실)도
사후 탐지했다 — 이후 재발 방지 골든과 주간 스캔으로 편입.

## 응답 계약 준수

| 계약 | 검증 |
|---|---|
| 답변 3원칙(근거 명시·구분 표시·정직 거절) | 서버 응답 검사기 + 계약 퍼저(무작위 인자 공격)로 스위프 |
| 침묵 절단 금지 | 목록 반환 도구 전수에 절단 명시·이어가기·파생수치 전수 계산의 3조건 기계 검사 |
| tombstone·버전체인 | 내려간 문서 질의 시 거절+후속 버전 안내, 검색 제외 — 골든 3종 |
| 레이트 리밋 정직 안내 | 골든 14종(fail-first·한도·회복·위조 저항·프록시 체인 실측 재현 포함) |

## 실사용 피드백 루프 (중구 실증)

실사용자 피드백 **13건 전량**을 "피드백 → 실패 재현 골든 → 수정 → 배포" 루프로 처리 완료.
수정마다 골든 39종·E2E 14문항이 회귀 가드로 남았다. 피드백이 소모되지 않고 검증 자산으로
축적되는 구조 — 이 루프를 공개 채널(GitHub Issues)로 확장한 것이 현재의 개방이다.

## 정직하게 공개하는 한계

- **파싱 잔차**: 노후 스캔 문서·복잡한 병합셀 표는 여전히 어렵다. 해당 문서는 `needs_review`로
  표시된 채 서빙된다(숨기지 않음). 수치 정본은 정형 축이 담당.
- **NAT 공유 한도**: 기관 내부망은 한 IP를 공유해 체감 한도가 낮을 수 있다(계측 보고 조정).
- **배포 전환 502**: 볼륨 부착 구조상 배포 전환 시 수십 초의 일시 오류가 있다(새벽 배포로 완화).
- **가용성 무보증**: 개인·비영리 운영의 best-effort다. 대신 감시 장치(워치독·업타임·자가 계측)를
  공개하고, 워치독 발동 0회를 성공지표로 관리한다.
